- (capability) CAP-1 Bind an Assistant to an Admin: Admin may assign to any Active Admin/Preacher; Preacher self-only; role lifecycle clears or requires the binding by destination role.
- (capability) CAP-2 Read and write the assigned Preacher's patch: contacts, sessions, attendance, dashboard and campaigns scoped to the assigned Preacher's personal patch.
- (capability) CAP-3 Open the operational surfaces: contacts overview/grid/reports, manage, sessions, dashboard, staff attendance, campaigns admin and contact form; same role set page+handlers.
- (capability) CAP-4 Keep a null patch empty: zero rows on every operational surface, surface-specific explanation, no dead Contacts/Manage/Invite nav.
- (capability) CAP-5 Make RLS match the patch: Assistant sees only the patch, Admin keeps programme scope, no service-role or page widening.
- (capability) CAP-6 Keep the Preacher label: 'Preacher' for both Admin and Preacher assignees, role shown where named, stored column unchanged, four roles unchanged.
- (constraint) Staff roles remain exactly four: Admin, Preacher, Volunteer, Assistant. 'Preacher' is the relationship label for the assigned staff member, not a fifth role.
- (constraint) An Assistant never receives programme scope; the Admin's programme scope stays unchanged.
- (constraint) An eligible assigned Preacher is Active, in the same programme, and role Admin or Preacher.
- (constraint) /volunteers is the Preacher's self-only surface; an Admin invites from /admin/invite. Only an Admin may demote an Assistant to Volunteer.
- (constraint) Keep assigned_preacher_id and assignedPreacherUserId; no supervisor_user_id. User-facing copy keeps 'Preacher' for both role cases.
- (constraint) The /contact form keeps its existing per-role assignment and collector rule; grid create stamps owner/actor, grid update preserves ownership.
- (constraint) The Admin's /sessions remains creator-only; the Assistant patch follows the dashboard's personal-scope definition.
- (constraint) The staff /attendance GET is in scope; the public attendance POST and registration are not.
- (constraint) dashboard_overview and campaign_progress are owner-only; the programme_attendance CTE is a programme-wide KPI input by design.
- (constraint) No new runtime service, table or environment variable; the proxy matcher gains /manage, /api/manage/*, /admin/* and /attendance.
- (note) Non-goals: programme-wide Assistant scope; a fifth/Supervisor role; per-assistant capability flags; renaming assigned_preacher_id; unifying collected_by_id; Assistants on /volunteers; changing the Campaign admin/caller split; changing the Admin /sessions filter; Next CVE upgrade.
- (note) Success signal: Admin invites an Assistant assigned to themselves; Assistant sees only the Admin patch across contacts, manage, sessions, dashboard, attendance and campaigns; Preacher's Assistant sees the Preacher patch; Volunteer paths unchanged; null patch empty; verify-rls and e2e pass; no user-facing 'Supervisor' string.
- (assumption) assigned_preacher_id can already hold an Admin's public.users.id; Admin-created contacts already do.
- (assumption) The Admin's existing Own scope dashboard predicate is the patch definition.
- (assumption) The autodialer AD-13 gate and the docs role matrix are updated in the same change.
