- (constraint) Parent spine architecture-folk_hkmc-2026-11-03 AD-1 (patch owner resolved once), AD-3 (one patch predicate / scope vector), AD-4 (role sets and surface matrix) are binding and inherited unchanged.
- (decision) The premium contact record is opened by inline triggers only. No global contact finder, no command palette, no URL deep link in this feature.
- (decision) Surfaces: session detail attendee table and phone cards; sessions overview Top 5 attendees; dashboard Focus rows and Candidates page; campaign assign-contacts grid; manage Sessions attendee pills. Campaign caller queue/call card/disposition and live attendance list are excluded. Manage Attendance and Favorites keep their existing detail panels.
- (decision) Campaign assign-contacts gets an explicit row expand control, matching the Contacts grid's leading-gutter affordance. It must not hijack row selection.
- (decision) The record is editable only when the contact is in manage/contact scope. Every other context is read-only. capabilities.canEdit and capabilities.canComment are server-derived, never inferred from the page.
- (decision) Session context deliberately keeps the cross-preacher read: an attendee of a visible session opens the full record read-only, including comments and campaign history. This crosses the comments patch rule and is an explicit product decision, not an accident.
- (decision) One record read model with two read contexts: manage (contact RLS, editable) and session (attendance in a visible session, read-only). A contact id alone never authorizes the session context. Manage context is the default; source is explicit.
- (decision) Session context authorizer: when sessionId is supplied, the contact must be an attendee of that visible session; without sessionId (Top 5 card), the contact must have at least one attendance row in a session visible to the caller. Reuse sessionsScope / getSessionAttendees where possible.
- (decision) One pure record view, two responsive frames (desktop dialog under the header, phone full-screen). The grid keeps its own open state and commit path for now; non-grid pages use a single ContactRecordProvider mounted in StaffAuthShell. The provider lazy-loads the heavy view chunk.
- (decision) One mutation channel: PATCH /api/manage/contacts. The provider merges ManageContactWriteResult into local record state; read-only contexts never expose an editor. No new write endpoint.
- (decision) Comments in session context are read-only: viewable, not writable. Comment writes remain patch-gated; the session context cannot post, edit, delete or react.
- (assumption) The provider is mounted once per staff shell and gated on ClientStaff.canReadContacts. A Volunteer never sees a record trigger.
- (deferred) Global contact finder / command palette; URL deep link ?contact=; converging the grid host onto the provider; a second record affordance in Manage Attendance/Favorites; campaign caller screens.
- (question) Spec placement: the existing spec-contacts-premium-grid withdrew CAP-5. A new spec-contact-record-access (with a supersession pointer in the old spec) is the cleaner home than reopening CAP-5.
- (version) Stack verified from package.json: Next 16.0.7, React 19.2.0, Tailwind 4.1.9, TypeScript 5, @supabase/supabase-js 2.105.1, @tanstack/react-table 8, @tanstack/react-virtual 3, Playwright 1.62, Vitest 5.0.5, pnpm 10.33.0.
